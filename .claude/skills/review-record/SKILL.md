# /review-record

`proof/` と `sample/*/` は**実際に回した記録**、手順書ではない。読者がここで判断するのは「**この主張をどこまで信じていいか**」

判定の基準は [.claude/rules/sample-readme-guidelines.md](../../rules/sample-readme-guidelines.md)（sample を読むと自動で渡る）

## 記録の性質 ── 書き換えてはいけないものがある

| 中身 | 直すか |
|---|---|
| 当時 実行したコマンド・当時のパス・当時 詰まった手順番号 | **直さない**（書き換えたら記録でなくなる） |
| 実測の数字 | **直さない**、合わないなら記録の側ではなく主張の側を疑う |
| 用語・表記 | 直してよい |

`proof/harness*.mjs`・`integrate.mjs`・`integrated-real.mjs`・`selfcheck.mjs` は**当時 実行した凍結スクリプト**、中身を今の実装に合わせない

## 先に読む

- 対象の記録（`proof/README.md` か `sample/*/README.md`）を**全部**
- その記録が指している**原本**（`sample/*/src/` `tests/` `task.md`・実測表）
- `README.md`（記録から数字と手順を引いている側）

## やり方

**観点は [doc-review-passes.md](../../rules/doc-review-passes.md) の A〜C を全部 通す**（見る観点を減らさない）、下は記録で特に効くものの詳細

### 1. 数字を実物から数え直す

**書いてある数字を信じない**、原本を開いて数える

| 数字 | 原本 |
|---|---|
| コスト・所要時間・呼び出し回数 | その走のログ（`proof/README.md` の実測表） |
| 生成物の行数 | `sample/*/src/` `tests/` の実ファイル（`wc -l`） |
| タスク文の文字数 | `sample/*/task.md` の該当ブロック |
| 変異の個数・生き残り | 変異チェックを**外から再実行**して確かめる |

**実際に起きた**: 「タスク文 381文字・実装15行・テスト44行」と書いてあったが、実物は **397文字・23行・55行**でどこからも再現できなかった

### 2. 母集団を確かめる

**「N走」「全部 合格」の N が何を数えたものかを書いているか**

**実際に起きた**: 「1タスク $0.41〜$1.43（10走）」と書いたが、**高い走は そもそも合格していない**ので合格した走だけ見ると必ず安く見えた（$6.74 の走は人に差し戻し）

- 落ちた走・差し戻された走も並べているか
- 「合格まで到達した走だけ」のような**選び方**を明示しているか

### 3. 都合の悪い結果が残っているか

記録の価値は**うまくいかなかった時に何が起きるか**にある

- 人に差し戻した回数・理由
- 何回 書き直したか
- **限界** ── その題材でゲートが保証しないもの（`sample-readme-guidelines` が必須にしている）

**実際に起きた**: 記事のループで「合格した記事の事実を嘘に書き換えてもテストは緑のまま通る」を実証して載せた ── 都合の良い結果だけ見せない

### 4. 誰が書いたかが1ファイルずつ分かるか

`sample/*/README.md` の「中身」の表で、**人 / AI** が明示されているか

- AI の生成物は**そのまま置く**、人が手を入れたなら手を入れたと書く
- 土台（動くベース・緑のテスト・設定・変異器）は人が用意したと書く ── 「人が書いたのはタスク文だけ」と書くと中身の表と矛盾する

### 5. 再現手順を実際に踏んだか

**成果物が動くことと、手順どおり再現できることは別**

**実際に起きた**: `bd create` が題名の500バイト上限に弾かれて詰まった ── 成果物は動いていたのに手順書だけが壊れていた

### 6. 本体 README との一致（数字と手順の両方）

README が記録から数字を引いている、片方だけ直すと黙ってずれる

```bash
cd /path/to/loop-engineering-playbook
grep -nE '\$[0-9]|変異[0-9]+|[0-9]+走' README.md proof/README.md sample/*/README.md
```

**sample が本体 README の手順との差分を書いているなら、その差分を数え直す**

**実際に起きた**: `sample/python-pytest/README.md` に「違うのは手順3・5・7 の**3つだけ**」と書いたが、13手順と実物を突き合わせたら**5つ**だった（6 テストコマンドと 11 起動時の環境変数が抜けていた）── 数えずに書いた

数え方 ── 本体 README の手順を1つずつ開き、その sample で**実際にやったこと**と比べる、記憶で書かない

## 出し方

**見つからなければ0件で返す** ── 数を埋めるために弱い指摘を足さない、根拠（ファイルと行）を書けないものは推測なので出さない

| 重大度 | 判定 |
|---|---|
| 高 | **読者や次の開発者が間違った行動をする**（実物と食い違う断定・数字の矛盾・画面と文書の食い違い） |
| 中 | **読み進めるのに引っかかる**（曖昧・前方参照・用語の割れ・未定義） |
| 低 | 表現の弱さ・重複 |

各件に **現在 / 実物ではどうか / 案 / 根拠（ファイルと行）** を付ける

## 終わったら

- `node .claude/scripts/inspect.mjs` が exit 0
- 数字を直したなら README 側も合っているか見る
