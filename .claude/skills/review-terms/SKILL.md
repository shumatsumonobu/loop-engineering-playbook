# /review-terms

用語は**1つの概念に1つの語、初出で定義**。これが崩れると読者は「これって何?」で止まり、そこから先を読まない

対象は**ドキュメントだけでなくコードも** ── 実行時に画面へ出る文言とコメントは読者の目に入る

## 静的な検査で済むものは先に回す

```bash
cd /path/to/loop-engineering-playbook
node .claude/scripts/inspect.mjs
```

**機械で判定できるもの（記号・絵文字・禁止した語）はここで落ちる**（何が対象かは実行すると項目ごとに出る・規約と根拠は [doc-guidelines](../../rules/doc-guidelines.md)）。このスキルが見るのは検査で判定できない側だけ

## 先に読む

- 対象の語を含む行を**全ファイル分**（`grep -rn <語> --include="*.md" --include="*.mjs" .`）
- `harness/integrated.mjs` の画面に出る文言（`log(` / `console.log(`）
- `README.md`（用語の定義がある側）

## やり方

**観点は [doc-review-passes.md](../../rules/doc-review-passes.md) の A〜C を全部 通す**（見る観点を減らさない）、下は用語で特に効くものの詳細

### 1. 未定義の語を探す

節を書き終えたら**その節で初めて出した語を全部 列挙**し、1つずつ「この文書のどこで定義したか」を答える。答えられない語は残さない

```bash
cd /path/to/loop-engineering-playbook
# 初出と定義の位置を比べる（初出が定義より前なら前方参照）、見るのは初出の位置だけなので3件で足りる
grep -n "<語>" README.md | head -3
```

**実際に起きた**: `ハーネス` は本文に20回 出るのに定義はツール表のセル内だけだった（表は読み飛ばされる）

### 2. 同じものを2つの語で呼んでいないか

**用語を足した時は既存の文書を全部 grep する**

**実際に起きた**: README が「3つのゲート」、DESIGN・proof・CHANGELOG・ハーネスのコメントが「3枚のゲート」で17箇所ぶん割れていた

### 3. 過負荷な語を探す ── 1語で複数の別物を指していないか

**これが一番 見つけにくく、一番 効く**

**実際に起きた**: 「機械」が主語として72箇所あり、**3つの別物**を指していた

| 指していたもの | 正しい語 |
|---|---|
| 合否を出すもの | ゲート／実物名（`npm test`・Stryker） |
| 手順を進めるもの | ハーネス |
| 人が判断しないという性質 | 自動で |

**見つけ方** ── その語を含む行を全部 出し、**行ごとに「何を指しているか」を書き出す**。2種類以上に分かれたら過負荷

```bash
cd /path/to/loop-engineering-playbook
grep -rn "<語>" --include="*.md" --include="*.mjs" . | grep -v node_modules
```

**直す時はファイル1つずつ**、置換したら `git diff -- <file>` を読んでから次へ。一括の `sed` は前回4箇所 壊した（文の欠落・同語反復・`＝` の2連）

### 4. 書き手の頭にある専門用語を出していないか

設計の言葉（契約・インターフェース・スキーマ・ペイロード）を読者向けに出さない、**何を書けばいいか**に翻訳する

| 出しがちな語 | 読者向け |
|---|---|
| 契約 | 返す値の形 |
| インターフェース | 関数の書き方 |
| スキーマ | 項目の並び |

**判定**: その語を消しても手順が書けるなら消す、消せないなら初出で1行 定義する

**実際に起きた**: 変異器の作り方を「契約」と書いた ── **コードのコメントに書いた語を、そのまま読者向けへ持ち出したのが原因**

### 5. 画面に出る文言に英語が残っていないか

導入した人が**必ず見る**ので、ドキュメントより優先度が高い

```bash
cd /path/to/loop-engineering-playbook
grep -rnE 'log\(`|console\.log\(`|console\.error\(`' harness/ proof/stub-worker*.mjs proof/new-sandbox.mjs
```

**`proof/` の凍結スクリプトは対象外**（当時の出力のまま残す記録）、対象は今も回すものだけ

**実際に起きた**: `survived 0/22`・`claim 成功`・`main統合: merged`・`実時間（wall）`・`→ skip`・`selfcheck` が出ていた ── README は同じものを日本語で書いていたので、**画面と文書で用語が割れていた**

`bd close --reason` に渡す文字列も**タスクの完了理由として残る**ので同じ扱い

## 出し方

**見つからなければ0件で返す** ── 数を埋めるために弱い指摘を足さない、根拠（ファイルと行）を書けないものは推測なので出さない

| 重大度 | 判定 |
|---|---|
| 高 | **読者や次の開発者が間違った行動をする**（実物と食い違う断定・数字の矛盾・画面と文書の食い違い） |
| 中 | **読み進めるのに引っかかる**（曖昧・前方参照・用語の割れ・未定義） |
| 低 | 表現の弱さ・重複 |

各件に **現在 / 実物ではどうか / 案 / 根拠（ファイルと行）** を付ける

## 終わったら

- `node .claude/scripts/inspect.mjs` が exit 0
- 語を1つ変えたら**全文書とコードを grep** して残りが無いか数える
- 検査を足したなら [MAINTAINING.md](../../../MAINTAINING.md) の「検査が効くか確かめる」を回す
