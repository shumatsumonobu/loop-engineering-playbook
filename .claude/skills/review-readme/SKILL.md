# /review-readme

`README.md` は**初見の読者が このループを導入先のプロジェクトへ入れるための手順書**、レビューはその1点で判定する

判定の基準は [.claude/rules/readme-guidelines.md](../../rules/readme-guidelines.md)（README.md を読むと自動で渡る）

## 先に読む

- `README.md` を**冒頭から最後まで通しで1回**（部分だけ見ると節をまたぐ矛盾が出ない）
- `harness/integrated.mjs`（手順の断定を突き合わせる相手）

## やり方 ── 視点を渡さず、断定を列挙して実物と照合する

**観点は [doc-review-passes.md](../../rules/doc-review-passes.md) の A〜C を全部 通す**（見る観点を減らさない・思いついた観点をその場で足さない）、下はそのうち README で特に効くものの詳細

**これは実測で差が出ている** ── 断定を1行ずつコードと突き合わせた回は連続で見つかり、視点を渡してレビューさせた回は**1件も出なかった**（[proof/README.md](../../../proof/README.md) の落とし穴25〜27）

だから**観点を頭に置いて読む**のではなく、**次の順で機械的に照合する**

### 1. 断定を列挙する

README から「〜だけ」「〜しない」「〜が要る」「〜で通る」の形を全部 抜き出す

```bash
cd /path/to/loop-engineering-playbook
grep -nE "だけ|しない|要る|不要|必ず|通る|できる|できない" README.md
```

### 2. 1件ずつ実装と突き合わせる

**推測で判定しない**、該当するコードを開いて確かめる

| 断定の種類 | 突き合わせる相手 |
|---|---|
| 導入先の要件（言語・テストランナー・置き場所・時間） | `harness/integrated.mjs` の `TEST_CMD`・`npmTest`・`allTests`・`WORK_ROOT`・`T` |
| ゲートの挙動 | `integrated.mjs` の 赤先行・凍結（`frozen` と `sha`）・変異チェック（`mutationCheck` / `MUTATOR`） |
| ワーカーの防御 | `undoWorkerCommits`・`revertOutsideWork`・`restoreTasksChangedBy`・`addedIgnoreMarks` |
| 実測の数字 | [proof/README.md](../../../proof/README.md)（README で数字を作らない） |
| 手順の中の環境変数・コマンド | 実際にその名前で読んでいるか（`process.env` を grep） |

**実際に起きた**: 「導入先は Node.js の JavaScript / TypeScript」「ここだけはハーネスの改造が要る」と書いてあったが、`MUTATOR` で差し替えられるので**どちらも誤り**だった（Python で実走して反証）

### 3. 読者が止まる所を探す

- **前方参照** ── 説明より前にその語を使っていないか（`grep -nE "ゲート|ハーネス|生き残り" README.md` の初出と定義の位置を比べる）
- **手順番号での参照** ── 番号の横に何をする手順か書いてある表だけ可（`inspect.mjs` が指している箇所を毎回 出す）
- **専門用語** ── 書き手の頭にある語（契約・インターフェース・スキーマ）を読者向けに出していないか
- **冒頭** ── 読者が何を得るかが分かるか、実装の制約（依存・言語）を先に見せていないか

### 4. 数字の一貫性

同じ量が2箇所で違う値になっていないか

```bash
cd /path/to/loop-engineering-playbook
grep -nE '\$[0-9]|[0-9]+分|[0-9]+秒|変異[0-9]+' README.md
```

**実際に起きた**: 「1タスク $0.41〜$1.43」と「1タスクあたり $0.5〜6.7」が同じ README にあった（母集団の選び方が違うのに、どちらも「1タスク」と書いていた）

## 出し方

**見つからなければ0件で返す** ── 数を埋めるために弱い指摘を足さない、根拠（ファイルと行）を書けないものは推測なので出さない

| 重大度 | 判定 |
|---|---|
| 高 | **読者や次の開発者が間違った行動をする**（実物と食い違う断定・数字の矛盾・画面と文書の食い違い） |
| 中 | **読み進めるのに引っかかる**（曖昧・前方参照・用語の割れ・未定義） |
| 低 | 表現の弱さ・重複 |

各件に **現在 / 実物ではどうか / 案 / 根拠（ファイルと行）** を付ける

## 終わったら

- `node .claude/scripts/inspect.mjs` が exit 0
- 直した後に**もう一度 読む** ── 修正が別の矛盾を生んでいないか（[doc-review-passes](../../rules/doc-review-passes.md) の「直す時」）
