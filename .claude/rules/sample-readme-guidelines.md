# sample の記録の基準（書く時・レビューする時）

`sample/*/` の README.md と task.md は**実際にループを回した記録**、導入手順書（[readme-guidelines.md](readme-guidelines.md)）とは目的が違う

文体・用語・事実の裏付けは [doc-guidelines.md](doc-guidelines.md)（同時に読み込まれる）

読者がここで知りたいのは「**何を渡したら 何が出てきて いくらかかったか**」と「**どこまで信じていいか**」

## 必ず書くこと

- **どのファイルを誰が書いたか**（人 / AI）を1ファイルずつ明示する
  - AI の生成物は**そのまま置く**、人が手を入れたなら手を入れたと書く
  - 土台なのか生成物なのかが1行で分かるようにする（読者が「どこまでが AI の出力か」を判断できる）
- **ループに渡したのはタスク文1つだけ**という前提を最初に示す（`task.md` へのリンク）
  - 土台（動くベースと緑のテスト）と設定も人が用意する、「人が書いたのはタスク文だけ」と書くと中身の表と矛盾する
- **実測** ── コスト・所要時間・`claude` の呼び出し回数・書き直し回数・変異の生き残り
  - 合格した回の値を書く、途中の失敗は別に書く
- **タスク文の書き方の理由** ── なぜその要素を仕様に入れたか（`task.md` 側に書く）
  - `task.md` には `bd create` に渡した文章を**原文のまま**載せる、原文の句点はそのままで良い
- **限界** ── この題材でゲートが保証**しない**もの
  - 実際に起きた: 記事のループで「合格した記事の事実を嘘に書き換えてもテストは緑のまま通る」ことを実証して載せた、都合の良い結果だけ見せない

## 再現手順

- **上から順に実行できる形**にする、複製 → インストール → 生成物を消す → 緑を確認 → 初期化 → タスク登録 → 実行 → **後片付け**
- **最初にどこで打つかを実コマンドで書く**（`cd /path/to/…`）、場所が切り替わる手順にも毎回書く
  - 実際に起きた: 起点が書かれておらず、1行目の `cp -r sample/… ../my-api` がハーネスのルート以外では失敗する案内だった
- **後片付けを省かない**
  - 実際に起きた: 手順が実行で終わっていて、作業コピー（約96MB）と不合格ログが残ったままになる案内だった
- 依存は**実走と同じ版が入る形**で書く ── JavaScript なら `package-lock.json` を同梱して `npm ci`、他の言語はその言語のやり方で
- `.gitignore` を同梱する ── **その sample を回すと生まれるものを漏らさない**（依存の置き場所・変異チェックが作るレポート・テストランナーのキャッシュ）、読者が複製せずその場で回してもリポジトリが汚れない
  - 確認は実物から ── `<リポジトリ外>` へ複製し、**依存を入れてテストと変異チェックを回して**（`claude` は呼ばない・$0）増えたファイルを数える
- AI の出力は毎回同じにならないと断る（書き直し回数もコストも上下する）

## 置く前に確認すること

- **このリポジトリの外へ複製して独立に検証したか**（複製先は `<リポジトリ外>`・[実験の作法](experiment-hygiene.md)）
  ```bash
  cd /path/to/loop-engineering-playbook
  rm -rf <リポジトリ外>/verify && cp -r sample/<name> <リポジトリ外>/verify && cd <リポジトリ外>/verify
  <依存を入れる>   # JavaScript なら npm ci、npm の依存が無い sample では不要
  npm test         # scripts.test が言語ごとのコマンドを呼ぶのでどの sample でも同じ
  ```
  複製先を消してからコピーする（残っていると入れ子にコピーされて別物を検証することになる）

  **`npm ci` を全部に当てない** ── 実際に起きた: `npm ci` を直書きしていて、`package-lock.json` を持たない sample（npm の依存が0）で exit 1 になった

  変異チェックも通す ── コードなら `npx stryker run`、自作の変異器なら default export を直接呼ぶ

  ```bash
  node --input-type=module -e "
  import mutate from './mutate-md.mjs';
  import { spawn } from 'node:child_process';
  const runTest = () => new Promise(r => spawn('npm',['test'],{cwd:process.cwd(),shell:true,stdio:'ignore'}).on('close',c=>r({code:c})));
  const res = await mutate({dir:process.cwd()}, ['<成果物のパス>'], { runTest });
  console.log('変異', res.total, '/ 生き残り', res.survivors.length);"
  ```
- **package.json の name が実験用の名前のままになっていないか**
  - 実際に起きた: リポジトリ外の検証用リポジトリの名前 `lep-article` のままだった、`package-lock.json` 側も同時に直して `npm ci` が通ることを再確認する
- **ハーネスをどう設定して回したか**が書いてあるか（環境変数・変異器の差し替え）
- **再現手順を上から実際に踏んだか**（成果物が動くことと 手順どおり再現できることは別）
  - 実際に起きた: 再現手順の `bd create` が題名の500バイト上限に弾かれて詰まった、成果物は動いていたのに手順書だけが壊れていた
