# 実験の作法

ここは**このリポジトリを開発する時の決まり**、導入する読者の手順ではない（読者向けは [README.md](../../README.md) と [sample/](../../sample/)）

コマンドを打つ時に効くので `paths` で絞れない、だから毎セッション読まれる

**① 実験はこのリポジトリの外でやる → ② 実験の一式はこっちの最新をベースにする → ③ 実験で確証を得たものだけ こっちへ反映する**

## リポジトリの外でやる

**このリポジトリの中で回さない** ── ハーネスやスタブを外へ持ち出し、外で回して、持ち帰るのは結果だけ

なぜ中で回さないか

- **意図しない変更が残る** ── 作業コピー・ログ・タスクの状態・生成物が このリポジトリに混ざる
- **ここに置きたいのは実験の結果** ── 途中経過が残ると、どれが結果か分からなくなる

置き場所を **`<リポジトリ外>`** と書く ── **実際の場所はその時に指示する**、実験が終わったら消す（散らばると消し忘れるので1箇所にまとめる）

**場所を指す語はこの2つだけ** ── 置き場所は `<リポジトリ外>`、そこに作るものは `リポジトリ外の検証用リポジトリ`

- 種類だけ言って場所を言わない語を使わない ── **中でも外でも通ってしまう**（実際に4種類・24箇所に割れていた）
- どの語が禁止かは `inspect.mjs` が持つ

- ハーネスを直す時も同じ、こっちのファイルを直接いじって回さない

## 最新をベースにする

**古い設定・古いデータで回した検証は結論ごと無効**

- ハーネスとスタブは `diff` で**意図した差分だけ**か確認してから持ち出す
- リポジトリ外の検証用リポジトリの設定と依存の版（`package.json`・`stryker.config.json`・ロックファイル）を今の要件に合わせる
- 使い回す時は回す前に初期状態へ戻す ── 戻し方は [MAINTAINING.md](../../MAINTAINING.md#ハーネスの回帰を回す)

## 確証を得たものだけ反映する

緑になったファイルだけ戻して、戻した側でもう一度 確認する

- **噛み合わない結果は緑に見えても捨てる**（例: ハーネスのログが1行も出ていないのに「完了」）
- もう一度 確かめたくなる検証は スタブごと [proof/](../../proof/) へ（リポジトリ外の検証用リポジトリは消すので残さないと二度と回せない）

## このリポジトリの作業ツリーを壊さない

- **破壊的な git 操作（`checkout` / `reset` / `clean`）を打つ前に必ず確認を取る**
- **検査やスクリプトが本当に効くかを確かめる時は、`<リポジトリ外>` へ複製してそこで壊す** ── このリポジトリのファイルを汚して `git checkout` で戻すのは禁止、手順は [MAINTAINING.md](../../MAINTAINING.md#検査が効くか確かめる)
  - 実際に起きた: 検査の動作確認のため `MAINTAINING.md` に1行 足して `git checkout` で戻し、**未コミットだった同ファイルの修正2箇所を消した**（「実験ではなく動作確認だ」と自分で分類して規約をすり抜けた）

## 課金

`claude` を呼ぶ操作は課金される、**実行前に見込み額を伝えて判断を仰ぐ**

制御フローの検証はスタブで $0（[proof/stub-worker.mjs](../../proof/stub-worker.mjs)）
