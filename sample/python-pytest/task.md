# タスク文

`bd create` に渡した文章そのもの、**ループに渡した指示はこれだけ**（動くベース・設定・土台のテスト・変異器は人が用意 → [README.md](README.md) の中身の表）

```bash
bd create "src/fizzbuzz.py に fizzbuzz(n) を実装" -d "<下の仕様>"
```

タスクの題名は beads の上限が**500バイト**（日本語なら約160文字）、長い仕様は題名に入らないので `-d`（説明）へ書く、ハーネスは題名と説明の両方をワーカーへ渡す

## 仕様（`-d` に渡した文章）

```
src/fizzbuzz.py に関数 fizzbuzz(n) を実装し、tests/test_fizzbuzz.py で pytest により検証する。仕様: 正の整数 n を受け取り、3の倍数なら文字列 'Fizz'、5の倍数なら 'Buzz'、15の倍数なら 'FizzBuzz'、どれでもなければ n を10進の文字列にして返す。境界（3・5・15・1・2）と 15の倍数が Fizz や Buzz より優先されることをテストで検証する。既存ファイル（src/greet.py 等）は変更しない
```

## 書き方の理由

| 書いたこと | なぜ |
|---|---|
| どのファイルに 何を作るか（`src/fizzbuzz.py`・`tests/test_fizzbuzz.py`） | ハーネスが成果物として見るのは `src/` と `tests/` だけ（外を書き換えても元へ戻される） |
| **pytest により検証する**と明記 | 言語とテストの道具を指定しないと、AI が JavaScript で書く余地が残る |
| 境界（3・5・15・1・2）を列挙 | 変異器が数値を +1 する壊し方を作るので、境界を検証していないと生き残る |
| 15の倍数の優先を明記 | 判定の順序を入れ替える壊し方に対応するテストが要る |
| 既存ファイルは変更しない | 既存ファイルの改変は 変異チェックがファイル単位で走るため通しにくい |

この題材では**1回目で合格**した、詰まらなかったので書き直しは発生していない
